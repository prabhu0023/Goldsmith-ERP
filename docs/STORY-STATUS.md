## Partial stories

- EP-01-S6 Developer can configure each environment from environment variables only: AC3-5 (staging and production values, production database access, hidden production secrets) need the cloud environments (D1a).
- EP-02-S1 Developer can apply and track schema migrations in every environment: AC5 (deploy applies migrations before the api serves) waits for the staging deploy (EP-01-S12, D1a).
- EP-03-S11 System can expose a rate-limit hook for EP-39 to fill in: the rate-limit hook is not called for GET /api/contract-version or an unknown operation name (FU-003, EP-39).
- EP-06-S1 System can store audit entries that cannot be updated or deleted: AC5 (grants check run in CI against staging) waits for staging (FU-008, D1a).
- EP-07-S2 System can stamp each event with a sequence number, entity id and version: AC5 (stock screen shows the refetched piece) needs the piece read of EP-22 and a live stock screen (FU-012, FU-013).
- EP-07-S9 User can see rail badge counts update live: no rail badge is server-backed yet; each moves to server counts with its screen (FU-012).
- EP-07-S11 System can carry each of the 10 catalogue events to its audience: AC4 (stock screen drops a billed piece live) needs the piece read of EP-22 and a live stock screen (FU-012, FU-013).
- EP-07-S12 Developer can test two browsers receiving each other's events: AC1 runs against a stand-in read until the piece read of EP-22 exists (FU-013).
- EP-38-S1 System can take a daily database backup: the production daily schedule is the RDS backup window, not built (D1a, FU-018).
- EP-38-S3 System can back up file storage: S3 versioning and the copy to another region or account are cloud work (D1a, FU-018).
- EP-38-S4 System can encrypt backups and keep them apart from live data: India region, operator-only IAM access and credentials that cannot delete backups (AC2-4) are cloud work (D1a, FU-018).
- EP-38-S5 Operator can receive an alert when a backup fails: the continuous-log alarm (AC3) is cloud, and delivery to a person needs EP-11 and EP-37 (FU-018).
- EP-38-S6 Operator can restore staging to a point in time: point-in-time restore and the production approver (AC1, AC5) are cloud; screen refetch (AC3, AC4) waits for live screens (FU-012, FU-018).
- EP-38-S8 Operator can follow a written restore drill and record its duration: go-live sign-off needs staging (AC4) and the drill reminder is cloud work (AC5) (FU-018).
- EP-38-S9 Operator can list sends made after a restore point for follow-up: provider message id, template and status need EP-11 and EP-12; no repeat wish needs EP-33 (FU-018).
- EP-38-S10 System can delete backups after the retention period: continuous-log retention (AC3) and S3 noncurrent-version expiry (AC4) are cloud work (FU-018).

Open follow-ups are in `docs/followups.md`. The EP-38 acceptance map is in `docs/setup/backup.md`.
